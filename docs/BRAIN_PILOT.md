# Brain: офлайн синтетический пилот (harness)

Статус: подготовка. Это не замер работающей Капри и не разрешение на live-хуки.

## Что это
`scripts/brain-shadow-pilot.js` (`runPilot()` для тестов; `node scripts/brain-shadow-pilot.js` печатает JSON и завершается с ненулевым кодом при `!passed` или сбое). 24 фиксированных синтетических случая «локальный чат / быстрый ответ» без запросов к инструментам, календарю, музыке и управлению ПК. Настоящий класс `Router` (`src/main/router.js`) с детерминированной заглушкой вместо model-callback (`chat`): моделей, сети, браузера и живого кода нет. Для каждого прогона — свежий `Router` и одинаковые явные часы (`i × 1000` мс).

Два прогона на парах: (1) базовый — только `Router.decide`; (2) тот же маршрут + побочный наблюдатель: `task-buffer` → `async-journal`. Наблюдатель получает копию решения, его ошибки и результат на решение не влияют, но любая ошибка наблюдателя, отказ буфера или журнала переводят `passed` в `false`. Слот буфера освобождается через `buffer.cancel(root)` в `finally`, дескриптор журнала — через `journal.close()` в `finally`. Решения сравниваются целиком (канонический JSON), компаратор подменяется в тестах (проверена детекция подмены решения).

## Что отчёт показывает
- `passed` и `checks`: `decision_parity` (24/24, 100%), `callback_parity` (`router_callback_calls` равны в обоих прогонах), `no_observer_errors` (`errors === 0`), `published_all` (`published === 24`), `events_submitted` (`submitted === 72`), `replay_equal` (`true`) и `no_synthetic_text` (`true`); `real_model_or_network_calls: 0` — по построению (есть только заглушка).
- `sidecar`: раздельный учёт `published` (увеличивается только после доставки всего пакета в журнал со статусом `accepted`/`duplicate`), `discarded`, `submitted`, `accepted`, `duplicate` и `errors` (только счётчик, без сырых текстов ошибок и содержимого).
- В журнал уходят только ID, enum и числа; текст случаев в журнал не попадает (проверяется поиском по файлу). Один источник на задачу; все события проходят схему ядра через буфер.
- Исход (`completed`/`failed`, часть случаев помечена как сбой) — утверждение harness, а не доказательство пользы реальной задачи.
- Журнал в уникальной папке `os.tmpdir()`; существующий файл не перезаписывается (повторный запуск с теми же ID даёт дубликаты без дозаписи: `accepted: 0, duplicate: 72`); проверяется точный replay и закрытие.
- Задержка наблюдателя: n=24, только среднее/максимум, как справка; p95/p99 и RSS не заявляются (`null`). Это не базовая линия железа.

## Согласованные пороги (без оценки в этом harness)
p95 ≤ 5 мс, p99 ≤ 20 мс, добавленный RSS ≤ 16 МиБ, без дополнительных вызовов модели/сети, без синхронного файлового ввода-вывода на горячем пути, нулевая утечка приватности в тестах. Пороги согласованы, но в этом стенде не оцениваются (`thresholds.verdict: null`); согласование порогов не разрешает live-хуки. Оценка качества решений (шаг 3) отложена.

## Покрытие (неполное)
Ответы роутера — заглушка, поэтому реальная работа роутера с моделью не проверена. Только локальный чат; внешние агенты и инструменты не входят. Интеграции с `main.js`, renderer, MCP нет.

## Стенд замеров этапа 3
`scripts/brain-baseline-bench.js` (`runBaselineBench()`, запуск через `node --expose-gc scripts/brain-baseline-bench.js` для учёта RSS или `node scripts/brain-baseline-bench.js`) выполняет парные офлайн-прогоны `baseline` (`brainShadow: false`) и `observed` (`brainShadow: true`) на синтетическом наборе `tests/fixtures/brain-baseline-set.json` (30 сценариев в 10 категориях, 63 реплики).

- **Что подключается:** реальный `Router` с детерминированной заглушкой `mockChat` (без Ollama, Electron, браузера и сети), `rpCommand`, `tor.wantsTor`/`onionLink`, `amygdala.salience`/`verdictOf`, `createChatGlue`, `createShadowHook` и `openRotatingJournal` во временной директории `os.tmpdir()`. Паузы между репликами (`> 120` с в `sil-01..03`) моделируются детерминированными виртуальными часами и таймерами.
- **Замеры (после прогрева 2 прогонов, `N = 30`, итого 1890 реплик):** синхронная задержка наблюдателя на горячем пути (`beforeTurn + startLocal + afterSuccess` через `process.hrtime.bigint()`, без `Router.decide` и фонового `flush`/`close`) в `timing.{p50,p95,p99}` (мс), плюс `rss_delta` до/после серии при запуске с `--expose-gc` (иначе `null` с пометкой).
- **Пороги и проверки:** `p95 ≤ 5` мс, `p99 ≤ 20` мс, `rss_delta ≤ 16` МиБ, паритет решений и вызовов `Router` 100%, 0 `observer_errors`, отсутствие текста реплик / `rendererId` / Tor-слов в `.ndjson`, совпадение `replay(ndjson).snapshot()` с `journal.snapshot()`, точные счётчики (`verified_pos = 4`, `verified_neg = 3`, `completed_turns = 47` на прогон, 0 записей для Tor/RP).
- **Ограничение:** полученные числа являются только справкой об офлайн-накладных расходах обвязки в Node, не измеряют живую Капри/Electron/Ollama и не включают `brainShadow`.
